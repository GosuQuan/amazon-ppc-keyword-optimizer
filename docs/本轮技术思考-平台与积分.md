# 本轮技术思考：平台、积分与企业模型定价

日期：2026-11-01。

## 问题

上一阶段已经有登录、方案隔离和“一次模型调用扣 1 次”。这不够支撑一个平台：用户登录后缺少主页，积分不能按服务区分，也没有和企业模型价格对应的规则。若直接照搬 YICOPY 页面价格，又会把查询工具套餐和 Ultra 广告方案混成一个价。

## 决策

1. 登录成功进入仪表盘。仪表盘只汇总当前用户的方案数量、可导出数量和积分，明细仍进广告工作台。
2. 沿用 SQLite 的 `ai_credits` 字段作为积分余额，避免再拆一套余额。新增 `account_plan`、`point_events`、`recharge_orders`。
3. 扣分和退分都写流水。生成方案若在保存前失败，退回刚扣的积分。首次导出在同一数据库事务里扣分，导出失败会随事务回滚，避免两个连接互相锁死。
4. 模型价格按账号类型和模型名计算。名称包含 `flash` 的模型用 Flash 价，其余用更高的其他模型价。缓存命中不扣分。连接失败退回本次模型积分。服务商返回 HTTP 错误不退，因为请求已经到达对方。
5. 充值只做演示入账。每一档每个用户只能入账一次。Ultra 档会把账号切到企业模型价。页面和接口都写明没有真实支付。

## 定价

价格量级参考 [YICOPY 官方价格](https://yicopy.com/pricing) 在 2026-10-31 可读到的结构，不是对方的报价单，也不是我们的收款凭证。

| 档位 | 标价 | 积分 | 对应关系 |
|---|---:|---:|---|
| 注册赠送 | ¥0 | 个人 1000 / 企业开通 20000 | 试用额度 |
| Pro 积分包 | ¥9.90 | 1500 | 对齐工具 Pro 的一次到账量级 |
| Max 积分包 | ¥49.90 | 10000 | 对齐工具 Max 的一次到账量级 |
| Ultra 企业池 | ¥3000 起 | 20000，并切换企业模型价 | 对齐 Ultra 起价量级 |

模型积分：个人 Flash 10、其他模型 25；企业 Flash 6、其他模型 15。生成方案 5，示例方案或旧示例分析 1，旧报告分析 5，首次导出草稿 2。

## 风险

- 演示充值默认开启。部署到多人环境前必须设置 `PPC_DEMO_RECHARGE=0`，否则登录用户可以给自己加积分。
- 企业开通码来自环境变量 `PPC_ENTERPRISE_CODE`。未配置时，提交开通码会被拒绝。
- 尚未验证浏览器里的仪表盘布局，也没有真实模型调用或支付回调。
