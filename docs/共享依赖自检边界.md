# 共享依赖自检边界

`brand-check.js` 与 `keyword-evidence.js` 是两套前端的单一业务来源。页面脚本目前大量使用 `window.xxx ? ... : fallback`，共享脚本加载失败（404、缓存损坏、加载顺序错）时会**静默降级**到本地兜底——行为可能悄悄变旧，用户不知道。

## 规则

1. 页面初始化时检查本页所需的共享函数清单：
   - 两版工具页必需：`buildReportEvidence`、`evidenceFor`、`evidenceLabel`、`adviceFor`、`sortByEvidence`、`charIssues`、`negativeCross`、`suggestPlacement`、`brandHit`。
2. 全部在位 → 静默通过（不打扰）。
3. 有缺失 → 在页面显著位置显示一次性警告条：「共享规则脚本缺失（列出函数名），业务规则已退回本地旧逻辑，请刷新或检查部署」——**不阻断页面**，但降级必须可见。
4. 自检本身失败不抛错（try/catch 包裹），避免自检成为新的故障点。

## 边界

- 只检测函数存在性，不校验函数行为（行为正确性由 125 项前端测试保证）。
- 警告条不写日志、不上报（本地工具，无遥测）。
- 两套前端共用同一检查函数（放 `keyword-evidence.js`），规则不分叉。
