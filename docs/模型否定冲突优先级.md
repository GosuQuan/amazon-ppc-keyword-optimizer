# 模型否定词冲突优先级

同一个候选词可能在不同广告数据中同时被标为无效词或亏损词，并与优质搜索词相同或存在字符串包含关系。模型建议的交叉判断优先显示“不建议否定”，即使同时命中无效或亏损证据。浏览器模型候选导出会排除此项。

测试覆盖无效词与亏损词同时命中、优质词包含以及模型候选导出。字符串包含只是人工复核线索，不证明亚马逊匹配语义或广告效果；规则独立生成的否定行及工作流导出不在此修复范围。

## 保护范围修正（2026-11-03）

原判定只把「优秀 / 良好」分类的搜索词当作需要保护的对象。实际测试发现：一条有订单但被规则评为其它分类的搜索词（如 ACOS 偏高但有成单）不会触发冲突提示，模型仍会建议否定它——这与后端「同组有订单记录即保护」的逻辑不一致。

现在保护范围改为**分类为优秀/良好，或有订单（orders > 0）**的搜索词。React 版与原生版同此口径。实测：报表里 `cell phone stand` 有 2 单，模型建议否定 `cell phone`，页面正确显示「⚠ 与优质数据冲突，不建议否定」。

仍存边界：字符串包含不等于匹配语义；判断依据只有本报表的订单与分类，不含广告位、时段与归因窗口。
