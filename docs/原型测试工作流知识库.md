### 出单概率测试结果实测（2026-11-04，`/indexPercentage/percentageIndex`，免费工具）

- 「开始分析 · 免费」；**出单概率 = 首页自然位覆盖率**：「看懂首页自然位覆盖如何影响关键词的自然出单机会」。
- **结果形态**（work_socks_ranking_B004QF0TFQ：10 ASIN × 10 词）：四档统计卡（5 高覆盖 / 0 中 / 1 低 / 4 无覆盖）；高概率词卡带**位置分层**（TOP3 高意图 / TOP8 主力曝光 / TOP16 可见范围，各带占坑数与占比）+ 建议动作；逐词表 17 列（出单概率 / 每页产品数 / 前3·前8·前16占坑数与占比 / 自然位 ASIN1-3 / 抓取时间 / 投放建议「优先投入/谨慎投入」）。
- **算法可从数据反推**：出单概率 = 目标 ASIN 集合的自然占坑总数 ÷（每页产品数 × 4 页）。例：work sock 占 10 坑 ÷ 48 = 20.8%。
- **数据解读指南**逐位置写明语义：TOP3 流量最高/意图最强/竞争贵；TOP8 稳定放量；TOP16 适合长尾。
- **对照我们**：这是「搜索排名」口径（需实时抓 Amazon SERP），我们无此数据源；可借鉴的是**位置分层的解读呈现**（我们的广告位报表本就有 TOP of search / Rest of search 分层，可把「位置语义解读」加到指标解读里）。双测试数值形态至此**两支全部实测闭环**。

- **四步流程**：上传三份 SP 报表（推广的商品、搜索词、广告位——与我们的三份高度一致，我们多一份 Bulk 用于取实体 ID）→ 店铺广告总览 → 按 ASIN 选择分析对象 → 核对全景广告架构。
- **输出物**：店铺广告总览（花费/销售额/订单/投放类型/匹配方式/广告位表现）、ASIN 列表（按商品看原始指标）、**广告组明细（按 ASIN 建议创建的广告组与投放目标）**、**每日预算与出价建议**、可执行文件（导出架构或生成 Amazon 批量操作表格）。
- **失败态承诺**：「处理失败时页面会显示原因和可执行的下一步」——与我们「阻断原因点名下一步」同思路。
- **对照我们的差距**：我们优化「已存在的投放」（调价/否定/新词），他们从报表推导「应创建的架构」（新广告组 + 每日预算）。我们没有**每日预算建议**与**按 ASIN 的广告组结构建议**，这两项是报表数据可支撑的（预算可从 ACOS 目标与销售额推导），可列为后续候选，但涉及策略假设需用户确认口径后再做。

**可复刻点（按性价比排序）**：
1. **导出前字符预检**：对我们导出的投放词/否定词做特殊字符检查（如引号、分号、非英文字符），在导出前列出并标注——纯本地规则，零成本，直接降低上传失败风险。
2. **AI 扩词的建议活动回填**：让用户为 AI 扩词选择目标活动/组（或按词根匹配已有活动），导出草稿时一并写入——需要一次交互，价值是少一步手工对齐。
3. 十一级架构是对方付费主打的输出形态，涉及信息架构重设计，不做轻量复刻。

### 流程控制台实测细节（2026-11-03 补充）

| 维度 | YICOPY 销词引擎 / 魔盒 | 我们 |
|---|---|---|
| 输入 | 1–10 个 ASIN + 站点/语言（插件端抓竞品 Listing） | 用户手动导出的搜索词报告 + 批量/推广商品/广告位报告 |
| 数据基础 | **竞品 Listing 标题/要点**、Alexa/COSMO 语义 | **用户自己的广告数据**（点击、花费、订单、ACOS） |
| 输出 | 关键词库（1,685 / 10,996 词）+ 来源证据 + 建议用法标签 | 调价清单、否定词、新词候选、词根、搜索词明细、动作草稿 |
| 结论形态 | 统计卡 + 高价值词前 10 + 必用/放标题标签 + 下一步动作 | 指标解读句、动作结论（含阻断原因点名）、复盘结论、五步进度条 |
| 流程串联 | 引擎→魔盒双测试→精准词→Listing/广告冷启动，前置条件写死 | 导入→分析→审核→导出→执行→复盘，前置条件如「缺 Bulk 不可导出」「未批准不可导出」 |
| 定位 | **扩张**：找新词、埋词、冷启动投放 | **优化**：对已有投放止损、调价、复盘 |

**结论：两者定位互补，不是同一功能的强弱对比。** 他们解决「该投什么词」，我们解决「已经投的词该怎么调」。因此不能简单说我们「落后」，但有几处**交互与呈现方式确实值得学**：

1. **来源证据列**：他们的每个词都带「N 个竞品使用 / N 标题 / N 要点」。我们的新词候选只有「来自收割/组合/AI」和一个理由文本，没有可核对的量化证据。可复刻：给新词加「在 N 条搜索词中出现」「带来 N 订单」等基于我们自己报表的证据列（注意：不能冒充竞品 Listing 证据）。
2. **建议用法标签**：必用 / 放标题 / 放要点 是可直接执行的结论，比我们的「优先级 P0/P1」更具体。可复刻：动作结论里加「建议先处理哪一类」的标签化指引（我们已有文字版，可升级为标签）。
3. **统计卡 + 方法论说明**：他们用三个数字概览 + 一大段「为什么这么做/不要怎么用」建立信任。我们有结论句但偏工程文案，可补「本次分析口径」说明。
4. **跨模块前置条件串联**：他们把「先双测试才能生成精准词」写进流程控制台并禁用后续按钮。我们的五步条有状态但未强制前置，可强化。
5. **成本透明**：任务配置摘要直接写「消耗 500 流量豆」，与我们「本次消耗 5 积分」同思路，已对齐。

## 0. 实测到的真实交互（本次新增，均来自真实登录态）

### 关键发现：免费工具要求先安装浏览器插件（2026-11-02 再次登录后实测）
重新登录成功后打开 `/tools/keyword-analysis`，页面先显示「正在准备关键词分析 → 正在确认当前页面与所选 Amazon 站点匹配，请稍等 → 检测中…」，随后变为：

> **完成安装后使用关键词分析；安装完成后请刷新本页。**（按钮：安装插件 / 刷新页面）

即**免费工具已被插件门槛挡住**：未安装 YICOPY 浏览器插件时，查询界面根本不出现，无法发起查询。

这同时解释了此前的失败：他们早期是**服务端抓取 Amazon**（所以我们遇到「Amazon 暂时限制了当前访问」的服务端限流），现在把抓取前置到**浏览器插件端**（客户端打开 Amazon 页面取数，绕开服务端限流）。这也是对方产品的重要设计决策。

**由此产生一个我们未做的复刻点**：YICOPY 用「插件 + 网页」组合解决数据源问题（`/extension-download` 是其插件分发页）。我们是纯服务端上传报表，没有插件形态，数据源完全依赖用户手动导出 CSV——这是我们相对对方的一个结构性差异，也是潜在的体验短板（用户必须去后台导报表）。

### 登录流程（含二次确认）
1. 任意页头「登录 / 注册」→ 弹出登录框，**默认微信扫码**，需切「邮箱登录」标签才出现邮箱/密码表单。
2. 提交后若账号已在别处登录，会出现**二次确认**：「这个账号正在另一台设备或浏览器中使用。继续登录后，原浏览器中的官网登录会退出；YICOPY Ultra 不受影响。」——必须点「继续登录」才完成登录。**此前几轮我漏掉了这一步，误以为登录不可靠，实为流程未走完。**

### 查流量结构工作区（核心免费功能，已跑到提交）
- 顶部：站点选择（🇺🇸 美国）、语言 EN、币种 USD 三处显式下拉，工具主标题带价格「查流量结构 · 60 免费工具算力」。

- **成本前置披露**：「本次查询消耗 60 免费工具算力，本月剩余 500 免费工具算力」——把消耗与余额同时摆在提交按钮旁。

|---|---|---|
| 查流量结构 | 60（快速30/标准60/深度90） | 示例 ASIN：B0CRT6HQ82、B0C3W4MNN1、B09FLNSYDZ |

### 实测遇到的真实失败态（四次尝试，两种文案）
- 查流量结构、关键词分析、以词找词三次提交，均返回：**「Amazon 暂时限制了当前访问，任务已停止。请稍后再试；如持续出现，请更换网络后重试。」**
- 第四次（约 2 小时后重试，按钮文案「关键词分析 · 10 免费工具算力」确认点中）返回：**「本次查询没有完成，请重新查询。」**
- 结论：其免费工具结果依赖现场抓取 Amazon，**当前账号/网络下无法完成任何查询**；本轮始终未拿到结果数据。

### 一个实证到的计费事实（有价值）
四次失败查询后，「本月剩余 **500** 免费工具算力」**始终未变**。这实证了他们页面写的「生成有效结果后计入本月使用量」——**失败查询不扣算力**。我们已用测试固定了同等行为：方案生成失败退积分（`test_failed_plan_creation_refunds_points`）、首次导出扣分且重复导出不扣分（`test_export_charges_once_and_repeat_export_is_free`），两边策略一致。

### 由此修正的对照要点
- YICOPY 的"算力"是**按次、按档位**明码标价的（30/60/90），比我们的统一积分更细；我们可按"导入规模/是否含 Bulk"设计分档。
- 他们把**成本、余额、站点一致性警告、示例值**全部前置在提交前，我们工作台虽有积分提示但缺少"本次会读取什么"的说明——可直接借鉴。
- 查询深度分档对应我们的报告粒度，我们目前无此概念。

## 1. YICOPY 的产品结构与核心路径

- Ultra 页底部明示「Ultra 太重太贵？先从免费的三件套开始」——向下兼容的回环。
- 每次查询前展示算力消耗，让用户把"查询"和"额度"心智绑定。
