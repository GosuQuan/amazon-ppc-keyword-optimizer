# 导出前字符预检边界

对标 YICOPY「SP 关键词字符检查器」：在把投放词 / 否定词写入 Amazon Ads 之前，先做一轮字符合规预检。我们的实现是**纯本地规则、只标注不阻断**。

## 判定规则（保守，避免误报）

对每个候选词（新词、否定词）检查：

1. **含非 ASCII 字符**（如中文、全角符号）→ `含非英文字符`——英文站点投放词出现中文通常是录入错误。
2. **含危险标点**（引号 `" ' " ' 、分号 `;`、竖线 `|`、反斜杠 `\`、尖括号 `<>`）→ `含特殊标点`——这些在批量上传模板中易出错。
3. **前后空格或连续空格** → `含多余空格`——会造成词不匹配或模板解析异常。

不检查：普通连字符、加号（广泛匹配合法）、数字、撇号在词中（如 men's 合法）。**不做任何阻断**——只输出提示，由人工决定是否修改。

## 展示位置

- 新词候选表与否定预判表：出现问题的词在「说明 / 理由」前加 `⚠字符:` 前缀。
- 不改变 CSV/TSV 导出的列结构；导出内容原样保留（上传由人工执行并负责）。

## 边界

- 本预检是启发式，不等于 Amazon Ads 的实际校验规则；未验证真实上传。
- 只覆盖字符层面，不判断词义、商标或类目合规。
- 两套前端共用同一实现（`keyword-evidence.js` 的 `charIssues`），规则不分叉。
