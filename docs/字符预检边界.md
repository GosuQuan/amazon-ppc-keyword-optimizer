# 导出前字符预检边界

对标 YICOPY「SP 关键词字符检查器」：在把投放词 / 否定词写入 Amazon Ads 之前，先做一轮字符合规预检。我们的实现是**纯本地规则、只标注不阻断**。

## 规则来源修正（2026-11-04，实测对方规则页后）

YICOPY 字符检查器页面明确引用 **Amazon Ads 官方规则：SP 手动关键词只能包含 letters, numbers, or spaces**（`? / " & \` 为官方举例禁止）。由此修正口径：

**旧口径（已废弃）**：只标三类问题，放行词中撇号与连字符（`men's`、`t-shirt` 视为合法）。
**新口径（对齐官方）**：**凡是非字母、数字、空格的字符都标记**——包括 `-`、`'`、`.`、`,`、`®` 等。依据官方规则本身，不再自行放宽。

具体检查项：

1. **含非 ASCII 字符**（中文、全角、®™© 等）→ `含非英文字符`。
2. **含非 [A-Za-z0-9 ] 字符**（连字符、撇号、点、逗号、引号等）→ `含官方外字符`。
3. **前后空格或连续空格** → `含多余空格`。

同时补齐对方页面的核心形态：**双栏清洗**——标注之外给出「清洗结果」（移除非法字符后的词），清洗后为空的词提示需人工改写。

## 展示位置

- 新词候选表与否定预判表：出现问题的词在「说明 / 理由」前加 `⚠字符:` 前缀（附清洗后词）。
- 不改变 CSV/TSV 导出的列结构；导出内容原样保留（上传由人工执行并负责）。

## 边界

- 「letters, numbers, spaces」来自 Amazon Ads 官方对 SP 手动关键词的规则表述；官方未公布完整黑名单，按白名单反向标记。close variants 对撇号等字符的实际容忍度未实测（需真实上传验证），清洗结果同样**只建议、需人工复核**。
- 只覆盖字符层面，不判断词义、商标或类目合规。
- 两套前端共用同一实现（`keyword-evidence.js` 的 `charIssues` + `cleanWord`），规则不分叉。
