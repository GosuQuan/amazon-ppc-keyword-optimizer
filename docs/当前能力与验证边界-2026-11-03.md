## 推送 GitHub 的可靠方法（2026-11-04 根因查明）

多轮「TLS connect error」根因：环境变量 **`ALL_PROXY=http://127.0.0.1:7897`**（curl 优先于 HTTP(S)_PROXY），且清空环境变量后仍有代理残留——只有 `git -c http.proxy='' -c https.proxy=''` 能彻底压掉。代理对 git TLS 握手间歇性掐断（SSL_ERROR_SYSCALL），而网页/API 正常，造成「网页 200 但 push 失败」的假象。

**可靠推法**（已实测直连握手成功）：

```
$env:ALL_PROXY=''; $env:all_proxy=''
git -c http.proxy='' -c https.proxy='' push origin iteration/yicopy-alignment
```

不动系统代理配置，代理继续留给浏览器用。
