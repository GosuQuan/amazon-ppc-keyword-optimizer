# 落地需求拆解与测试边界（供审核）

对照《技术方案 v1》与《竞品对比与可行性分析》，将核心功能点拆解为可验收的落地需求。
每条需求标注：**【现状】**（已验证 / 已实现待加固 / 缺失）、**优先级**、**测试边界**（输入边界 / 异常路径 / 验收标准）。

**工作约定（审核通过后执行）**：按 P0 顺序逐项实现 → 每项实现前以本文档该条的测试边界为准 → 实现后按边界逐条回归并汇报结果 → 每完成一项交付一次（更新工具 + 验证记录），不批量堆叠。

## 测试边界总纲（适用于所有需求，不再逐条重复）

1. **数据形状**：0 行 / 仅表头 / 单行 / 1 万行 / 10 万行（性能目标：解析 <5s、分析 <3s、页面不卡死）
2. **表头**：列顺序打乱、列缺失、列名大小写与全半角混用、双语括号列名
3. **数值**：0、负数、超大值、空、`-`、`—`、千分位、货币符号、百分比、文本混入
4. **语言**：纯英文 / 纯中文 / 中英混排 / 含 emoji / 含逗号引号换行的引用字段
5. **环境**：file:// 直开 与 http://127.0.0.1:8787/tool 两种打开方式行为一致（AI 除外）；localStorage 可用 / 被禁用（降级默认值不报错）；断网（AI 降级为规则模式）
6. **幂等**：重复导入同一文件不叠加记录；同参数重复分析结果一致；重复导出内容一致
7. **通用防御**：任何单行脏数据不得中断整体分析；异常在界面可见（文件级错误标注），不得静默吞掉

## F1 数据接入与解析

### R1.1 搜索词报告 CSV 导入　【现状】已验证　P0（保回归）
- **需求**：商品推广搜索词报告 CSV/TXT 导入；中英/双语表头映射；UTF-8/GB18030 自适应；多文件合并；带引号字段解析；文件级行数与错误标注。
- **测试边界**：
  - 输入：zh 表头、en 表头、双语表头、BOM/无 BOM、GBK、Tab 分隔
  - 异常：空文件、仅表头、表头不可识别（报错含文件名）、数值列混入文本
  - 验收：63 行示例报表 → 记录 63；抽查 花费=点击×CPC（±0.01）；重复导入同名文件行数不翻倍

### R1.2 真实出价接入：关键词报表 / 批量表解析与关联　【现状】缺失　**P0**
- **需求**：新增导入「商品推广关键词报表」与亚马逊批量表（Bulk，Tab 分隔）中的 keyword 记录，提取**真实当前出价**；按 广告活动+广告组+关键词+匹配类型 关联到搜索词分析结果；关联不上的关键词回退「历史最高 CPC×1.15」估算并标注"估"。
- **测试边界**：
  - 批量表含多种 Entity（Campaign/Ad group/Keyword/Ad/Negative…）：**只取 Keyword 行**
  - 出价字段：空、`-`、0.00、两位小数、带货币符
  - 同一关键词出现在多个文件且出价不同：**以后导入的文件为准**，并在提示区注明覆盖数
  - 搜索词报告有、关键词报告无的投放 → 回退估算（"估"标）
  - 关键词文本规范化匹配（大小写/多余空格），但**不模糊匹配**（避免错挂出价）
  - 验收：动作表「现出价」列，真实出价显示原值不标"估"，回退行标"估"；构造 5 条关联 / 2 条不关联用例全部正确

### R1.3 日期与多周期趋势　【现状】日期列已捕获未使用　P1
- **需求**：按日期聚合输出每日 花费/销售额/ACOS/订单 迷你趋势；支持按日期范围过滤后再分析。
- **测试边界**：无日期列（趋势区自动隐藏）；跨年日期；周报格式（周一起始）；单日报告；日期文本格式不一
- **验收**：构造 7 天数据，7 个日桶汇总=总数

### R1.4 商品投放 / ASIN 报告　【现状】缺失　P1
- **需求**：解析商品投放报告；search term 为 ASIN（B0 开头 10 位）单独归类；支持对 ASIN 的否定与收割建议（进入商品投放否定清单）。
- **测试边界**：ASIN 大小写、伪装 ASIN（b0x12，长度≠10）、普通词与 ASIN 混排；无关键词列（商品投放报告特性）

## F2 分级引擎

### R2.1 七级分级规则　【现状】已验证　P0（保回归）
- **规则**：优秀(ACOS≤0.6×目标) / 良好(≤目标) / 偏高(≤1.5×目标) / 亏损；无订单词按「允许花费=点击×预期转化率×目标ACOS×客单价」分 无效/观察/潜力。
- **测试边界**：sales>0 但 orders=0；sales=0 且 spend>0（ACOS=∞ 显示 `-`）；clk=0 但 spend>0；客单价缺省 25 的提示；target=100%、minClicks=1 端值；某级为空不渲染空卡片
- **验收**：内置构造数据集覆盖 7 级各 ≥2 条，断言全对（做进 R-T0 回归集）

### R2.2 低曝光标记　【现状】已实现（并入理由文案）　P1（保回归）
- **测试边界**：impFloor=0（不标）；impFloor 极大（除无效/亏损外全标）；与"维持观察"叠加时文案不重复

## F3 调价引擎

### R3.1 调价引擎切换真实出价　【现状】估算版已实现　**P0**
- **需求**：盈利出价上限=目标ACOS×客单价×转化率；有真实出价时 `建议出价` 直接基于真实值计算并给出绝对值与幅度；无真实出价回退估算并标"估"。动作含：提价抢量 / 小幅提价 / 维持 / 小幅降价 / 降价 / 降价并否定 / 暂停。
- **测试边界**：
  - cvr=0（有点击无订单）不产生提价；ceiling<最低出价 → 建议"暂停/否定"
  - 优秀词 ceiling>proxy×(1+提价上限) → 封顶在上限
  - 降价后 newBid<floor → 转为"暂停"
  - 调整幅度按上下限截断（默认 +30%/-50%）
  - **R1.2 关联失败的行必须回退估算且理由注明"基于估算出价"**
- **验收**：R-T0 构造集上 6 类动作断言全对；真实出价行与估算行的"估"标注正确

### R3.2 无效词 exact 投放的处理　【现状】已实现（暂停路径）　P0（保回归）
- **测试边界**：exact 投放无效 → 只出现在调价清单（暂停），不得同时进否定清单；broad/phrase/auto → 同时出现在否定清单

## F4 否定引擎

### R4.1 无效搜索词精准否定　【现状】已验证　P0（保回归）
- **测试边界**：clk<minClicks 不否定；同词多来源去重（camp+adg+词）；否定词含逗号/引号的 CSV 转义；导出列完整（方式/词/活动/组/来源/点击/花费/理由）

### R4.2 亏损词根词组否定 + 优质词冲突保护　【现状】基础已实现；**冲突保护缺失**　**P0**
- **需求**：词组否定候选生成后，**新增保护检查**：若该词根（或其子串）出现在任何 优秀/良好 搜索词中 → 不给词组否定建议，降级为"观察"并提示冲突（列出受影响的优质词，人工决策）。
- **测试边界**：
  - 词根"bottle"在 11 个无效词中出现、但也在 1 个优秀词中出现 → 不否定，给冲突提示
  - 词根与其二元组同时命中（water 与 water bottle）→ 只保留更具体的一个？否——**都列出但去重标记包含关系**
  - 盈利词根优先级恒高于亏损（同一词根 sales>0 时永不否定）
  - 冲突提示需含受影响优质词的销量，供人工权衡
- **验收**：构造"词根同时命中优质与无效"用例 → 不产生词组否定、产生冲突提示；纯亏损词根 → 正常否定

### R4.3 互搏检测与否定　【现状】已验证　P0（保回归）
- **测试边界**：两位置均 0 订单（winner 按花费少者）；winner 也亏损（ACOS>1.5×目标）时建议改为"合并到预算更优者"；点击<minClicks 的词对不检测；否定建议落到具体 camp+adg

### R7.2 亚马逊批量表（Bulk）格式导出　【现状】缺失　**P0**
- **需求**：在导出中心新增「批量表(TXT)」：生成可直接在广告后台批量上传的三类行——
  1. 调价行：Entity=Keyword，Operation=Update，带 Campaign/Ad Group 名称列、Keyword Text、Match Type、**Bid**（有 ID 时带 ID 列）
  2. 否定行：Entity=Negative Keyword，Match Type=Negative Exact/Negative Phrase
  3. 新增行：Entity=Keyword，Operation=Create，Match Type=Exact + 建议出价
  列集以亚马逊 SP 批量表 v2 模板对齐；实现时以用户提供的真实批量表表头做一次对齐校验。
- **测试边界**：
  - 无 ID（用户未提供原批量表）→ ID 列留空、名称列齐全（依赖后台按名称匹配），并在导出前提示
  - bid 两位小数、无货币符；暂停行 State=paused；否定行不填 Bid
  - Campaign/Ad Group/关键词 含逗号制表符引号 → TXT 转义
  - 三类行可分别勾选生成（联动 R7.3 P1 前先全量）
  - 验收：用文本编辑器打开可直接读；与 R1.2 联通后，调价行 Bid=真实出价计算结果
- **依赖**：R1.2（ID/名称锚点与真实 bid）
