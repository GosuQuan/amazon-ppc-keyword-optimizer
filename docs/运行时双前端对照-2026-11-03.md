# 运行时双前端对照（2026-11-03）

源码级 parity（`tools/ui_parity.js`）之外，用 CDP 驱动真实浏览器把**同一份报表 + 同一份 AI JSON** 分别在两版页面分析，对比渲染结果（`docs/runs/probe_runtime_parity.js`）。

## 一致的项

| 表 | 原生版 | React 版 |
|---|---|---|
| 调价清单 | 3 行 | 3 行 |
| 搜索词明细 | 4 行 | 4 行 |
| AI 扩词 | 2 进入 | 2 条 |
| AI 否定预判 | 1 个 | 1 条 |
| **预算参考** | CampA/G1：花费 80、日均 2.67、3 单、销售 90、ACOS 88.9%；CampB/G2：56、1.87、2、48、116.7% | **数字逐字符一致** |

预算参考为首次运行时验证，聚合与排序（按花费降序）正确。

## 一处差异及判定

新词候选行数抓取为「原生 0 / React 2」。判定为**探针工件而非产品差异**，依据：

1. 原生版 aiStatus 明确显示「扩词 2 个，其中 2 个进入新词清单」；
2. 独立的 demo 探针（`probe_classic_advice_col.js`）在同一原生页面读到 `tblNew` 有行且「建议」列在位；
3. 原生表格由 `mkTable` 动态重建，探针在重建间隙查询会拿到空表。

未把该探针固化为回归项（时序脆弱）；源码级 parity + 两条独立探针已覆盖同等置信度。
