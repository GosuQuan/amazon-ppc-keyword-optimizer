# 模型用量测试边界

本轮仅实现后端 SQLite 用量账本与查询 API，不做预算、缓存、费用估算或真实模型调用。先于实现制定本边界。

## 存储与隐私

- 独立模块和 `ai_usage` 表；数据库路径优先 `AI_USAGE_DB_PATH`，其次 `PPC_DB_PATH`，默认 `backend/data/workflow.sqlite3`，不修改 workflow 表。
- 每次实际发起 upstream 请求记录一次。取 token 的本机请求不计入；本地 400 拒绝不计入。
- 仅保存 id、provider hostname、model（最多256字符）、HTTP status、内部 success 标志、duration_ms、三项 token 数、UTC created_at。无 HTTP 响应时 status 为 null；响应解析失败保留真实 HTTP 状态但计失败。
- 不保存 prompt、密钥、响应正文、reasoning、URL 路径/query、错误正文。费用始终 null。
- usage 每项仅接受非负 JSON 整数，排除 bool、浮点数、字符串、负数；缺失/无效为 null，合法零保留。不推算 total_tokens。不因极大整数溢出影响响应。
- 账本写失败不得把成功模型响应变成 502，不得触发再次调用；仅记录固定、不含请求内容的日志。

## 查询契约

`GET /api/ai/usage` 返回 `{summary, records}`。records 按 id 降序最多50条，每条含上述公开字段、`success`（仅表示上游 HTTP 成功且响应可解析，不表示建议有效）及 `cost: null`。

summary 为全部历史的 `calls`、`successes`、`failures`、`prompt_tokens`、`completion_tokens`、`total_tokens`、`prompt_known_calls`、`completion_known_calls`、`usage_known_calls`、`cost: null`。usage_known_calls 表示 total_tokens 已知条数。每项 token 仅累加已知值，没有已知值则 null，不能将部分已知合计描述为完整消耗。网络/HTTP/解析失败计失败。

## pytest 验证矩阵

1. 成功响应、合法 usage、真实零、耗时与时间、hostname 提取。
2. 缺失 usage、非字典 usage、非法 token 类型以及极大整数；缺失保持 null。
3. HTTP 429/500、连接失败、非 JSON 成功响应；一次请求一条记录，错误保持现有安全提示。
4. prompt/key/response/reasoning/query 哨兵不出现在数据库和查询结果；检查表结构白名单。
5. 自定义地址缺独立密钥返回400，无网络调用且无记录。
6. 最近50条与全历史汇总、空账本、已知计数及 null 费用。
7. 数据库路径隔离、与 workflow 表共存、写入失败不破坏模型响应。

所有 AI 测试以临时目录数据库和 mock urlopen 执行，默认阻断网络；不读取 `.env`，不实际调用模型。完成后运行 AI 定向测试及后端全量回归并记录命令和结果。
